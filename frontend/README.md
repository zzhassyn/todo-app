# todo-app · frontend

React + Vite клиент для Go-бэкенда из корня репозитория.

## Дизайн

Интерфейс задуман как буфер текстового редактора, а не как карточки или
чат-лента: каждая задача — строка с номером, диф-маркером (`+` активная,
`−` выполненная) и чекбоксом `[x]`. Слева — постоянная боковая панель
(системные фильтры и список папок), снизу — узкая статус-строка в духе vim
(`NORMAL`/`ARCHIVE`, аккаунт, `:q` для выхода). Палитра — тёплая, землистая
(gruvbox-вдохновлённая), а не дефолтный чёрный фон с неоновым акцентом.
Шрифты: `Fragment Mono` для интерфейса, `Newsreader` зарезервирован для
крупных акцентных чисел.

## Создание задач: inline-синтаксис

Поле добавления задачи понимает разметку прямо в тексте — отдельных полей
для тегов/приоритета нет:

- `#tag` — добавляет тег (можно несколько, дубликаты игнорируются);
- `!low` / `!medium` / `!high` — задаёт приоритет (если не указан, бэкенд
  использует `medium` по умолчанию).

Например: `написать отчёт #work #q3 !high` создаст задачу с заголовком
«написать отчёт», тегами `work`/`q3` и высоким приоритетом. Под полем
показывается живая подсказка с тем, что будет распознано. Срок выполнения
(due date) задаётся отдельным переключателем справа от поля ввода, а не
через inline-синтаксис — даты сложнее надёжно парсить из свободного текста.

Парсер лежит в `src/utils/parseTaskInput.js` и не зависит от React — это
чистая функция, которую легко гонять отдельно при изменении.

## Папки / списки

В боковой панели под системными фильтрами — секция «мои списки»: каждая
папка — это сущность на бэкенде (`POST/GET/DELETE /api/v1/folders`), не
просто клиентский тег. Клик на папку:

- подсвечивает её в сайдбаре;
- меняет заголовок буфера на её название;
- грузит задачи через `GET /api/v1/tasks?folder_id={id}` — это отдельный,
  независимый от системных фильтров «вид»; задачи внутри папки не
  показываются в «все»/«активные»/«выполнено» и наоборот.

Композер, пока выбрана папка, автоматически подмешивает `folder_id` этой
папки в тело запроса при создании задачи — никакого отдельного выбора
папки в самой форме нет, контекст берётся из того, что выбрано в сайдбаре.

Создание папки — кнопка «+ новый список» превращается в поле ввода;
`Enter` отправляет `POST /folders` и добавляет папку в список, `Escape`
или пустой `blur` отменяет ввод без запроса. Удаление — крестик,
появляющийся при наведении на папку в списке; бэкенд при этом каскадно
удаляет все задачи внутри папки физически (не в архив, см. README в корне
репозитория) — если удаляется активная в данный момент папка, вид
откатывается на системный фильтр «все».

## Архив

Архивация — это единственный способ убрать задачу из обычных списков:
кнопка `⌫` на строке задачи отправляет `POST /tasks/{id}/archive`, задача
пропадает из текущего вида (системного или папочного — архивация работает
одинаково в обоих), но остаётся доступной в системном фильтре «архив» в
сайдбаре, откуда её можно восстановить (`↺`). Архив подгружается лениво —
только при первом открытии вкладки за сессию.

## Запуск

```bash
npm install
cp .env.example .env   # при необходимости поменять VITE_API_BASE_URL
npm run dev
```

По умолчанию клиент ходит на `http://localhost:8080/api/v1` — это адрес
Go-бэкенда из `docker-compose.yaml`/`Makefile` в корне репозитория.

## Аутентификация

Бэкенд выдаёт JWT в httpOnly cookie (`/auth/register`, `/auth/login`).
Все запросы клиента идут с `credentials: "include"`, поэтому:

- бэкенд должен быть запущен с `HTTP_ALLOWED_ORIGIN`, равным origin'у этого
  фронтенда (по умолчанию `http://localhost:5173`, т.е. `npm run dev`);
- при разработке на разных портах/доменах это обязательно must — без
  совпадающего CORS-конфига браузер откажется сохранять cookie.

## Структура

```
src/
  api/client.js          обёртка над fetch (credentials, разбор ошибок)
  context/AuthContext.jsx состояние аутентификации (user, login, register, logout)
  utils/parseTaskInput.js парсер inline-синтаксиса (#тег, !приоритет)
  components/
    AuthScreen.jsx        вход / регистрация
    Sidebar.jsx             боковая панель: системные фильтры + папки/списки
    Buffer.jsx               список задач ("открытый файл"), заголовок зависит от view
    BufferLine.jsx            одна задача-строка (приоритет, теги, срок, архивация)
    Composer.jsx              строка добавления новой задачи + due date + folder_id
    StatusBar.jsx             нижняя статус-строка (режим, аккаунт, выход)
    Toast.jsx                 всплывающее сообщение об ошибке
  app.css                 все стили компонентов
  index.css               токены дизайна (CSS-переменные) и сброс стилей
```

Состояние «что сейчас показано» в `App.jsx` — единое значение `view`:
либо `{ type: "system", key: "all" | "active" | "done" | "archive" }`,
либо `{ type: "folder", id, title }`. Это сделано намеренно одним полем,
а не отдельными `filter`/`selectedFolderId`, чтобы подсветка в сайдбаре и
содержимое буфера не могли разойтись между собой.

## Сборка

```bash
npm run build
```

Собранные файлы попадают в `dist/` — раздавайте их любым статическим
сервером или через nginx/Caddy перед Go-бэкендом.
