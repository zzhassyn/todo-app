# todo-app · frontend

React + Vite клиент для Go-бэкенда из корня репозитория.

## Дизайн

Современный SaaS-интерфейс в духе Linear/Notion/GitHub Projects (но не
копирующий их): три колонки — sidebar / список задач / панель деталей,
светлая тема по умолчанию с полноценной тёмной темой, один акцентный
цвет (терракотовый) на весь интерфейс. Все цвета и метрики — CSS-переменные
в `src/index.css`, переключаемые через `[data-theme="dark"]` на `<html>`;
никаких отдельных light/dark файлов стилей.

Список задач — плоские строки без карточек-теней на каждый item: кружок-
чекбокс, цветная точка приоритета, заголовок, под ним — относительная дата
(«Сегодня», «Завтра», «28 июн») и нейтральные бэйджи тегов. Кнопка
архивации появляется по hover, не висит постоянно.

## Three-pane layout

```
┌──────────┬────────────────────┬───────────────────┐
│ Sidebar  │ Список задач       │ Детали задачи      │
│ (фикс.)  │ (растягивается)    │ (появляется при    │
│          │                    │  выборе задачи)    │
└──────────┴────────────────────┴───────────────────┘
```

Панель деталей не резервирует место, когда закрыта — список занимает всю
ширину. На экранах уже 1024px панель становится полноэкранным оверлеем
вместо третьей колонки. Sidebar на экранах уже 860px превращается в
горизонтальную панель сверху (список папок скрывается — он не критичен
для большинства мобильных сценариев и его всегда можно открыть из
системного фильтра «Все», переключившись обратно на десктоп).

Выбор задачи (`selectedTaskId` в `App.jsx`) — состояние, не зависящее от
текущего вида (`view`): можно открыть деталь любой задачи поверх любого
системного фильтра или папки.

## Создание задачи: без модальных окон

Поле быстрого добавления — обычная строка в начале списка, не модалка.
Кнопки выбора даты/приоритета/тегов скрыты, пока поле пустое, и появляются
сразу после первого введённого символа (progressive disclosure — документ
явно просил «максимально сократить количество кликов», поэтому лишние
элементы управления не показываются, когда не нужны). Каждая кнопка
открывает компактный popover:

- **Дата** — `src/components/DatePicker.jsx`: собственная сетка месяца
  (6×7 дней, понедельник первым), навигация по месяцам, подсветка
  сегодняшнего и выбранного дня, кнопки «Сегодня»/«Очистить». Без
  `<input type="date">` и без внешних библиотек дат — вычисления в
  `src/utils/date.js` на чистом `Date`.
- **Приоритет** — `PriorityPicker.jsx`: три варианта с цветными точками
  (низкий — зелёный, средний — жёлтый, высокий — красный).
- **Теги** — `TagPicker.jsx`: поиск по существующим тегам + создание
  нового по Enter, если совпадений нет (бэкенд делает find-or-create по
  имени, так что фронтенд не различает «выбрать существующий» и «создать
  новый» — это один и тот же запрос).

Если выбрана конкретная папка (см. ниже), `App.jsx` подмешивает её
`folder_id` в payload создания автоматически — в самой форме нет поля
выбора папки, контекст берётся из того, что открыто в sidebar.

## Sidebar: системные фильтры + папки

Системные фильтры — Все / Сегодня / Активные / Выполненные / Архив.
«Сегодня» вычисляется на клиенте (сравнение `due_at` с текущей датой) —
у бэкенда нет отдельного эндпоинта для диапазонной фильтрации по дате,
есть только `completed`/`archived`/`priority`/`tag`/`folder_id`.

Папки — отдельная сущность на бэкенде (`POST/GET/DELETE /api/v1/folders`).
Клик на папку подсвечивает её, меняет заголовок списка на её название и
грузит `GET /api/v1/tasks?folder_id={id}` — независимый от системных
фильтров вид; задачи внутри папки не показываются в «Все»/«Активные» и
наоборот. Создание — кнопка «+ Новый список» → инпут → `Enter`. Удаление —
крестик по hover; бэкенд каскадно удаляет все задачи внутри папки
физически (не в архив — см. README в корне репозитория), поэтому при
удалении активной в данный момент папки вид откатывается на «Все».

Состояние «что сейчас показано» в `App.jsx` — единое значение `view`:
либо `{ type: "system", key }`, либо `{ type: "folder", id, title }`.
Сделано намеренно одним полем, а не отдельными `filter`/`selectedFolderId`,
чтобы подсветка в sidebar и содержимое списка не могли разойтись.

## Архив и безвозвратное удаление

Кнопка архивации на строке задачи (или «Архивировать» в панели деталей)
отправляет `POST /tasks/{id}/archive` — мягкое удаление, задача пропадает
из текущего вида, но доступна в системном фильтре «Архив», откуда можно
восстановить. У архивной задачи в панели деталей вместо «Архивировать»
показываются «Восстановить» и **«Удалить навсегда»** (с подтверждением) —
последнее вызывает `DELETE /tasks/{id}/permanent`, который на бэкенде
разрешён только для уже архивированных задач. Это единственный путь к
безвозвратному удалению задачи в интерфейсе.

## Тема

`src/utils/useTheme.js` — небольшой хук: читает сохранённую тему из
`localStorage`, иначе берёт `prefers-color-scheme`, ставит
`data-theme="light"|"dark"` на `<html>`, сохраняет выбор. Переключатель —
иконка солнца/луны в подвале sidebar.

## Запуск

```bash
npm install
cp .env.example .env   # при необходимости поменять VITE_API_BASE_URL
npm run dev
```

По умолчанию клиент ходит на `http://localhost:8080/api/v1` — это адрес
Go-бэкенда из `docker-compose.yaml`/`Makefile` в корне репозитория.

## Аутентификация

Бэкенд выдаёт JWT в httpOnly cookie (`/auth/register`, `/auth/login`).
Все запросы клиента идут с `credentials: "include"`, поэтому:

- бэкенд должен быть запущен с `HTTP_ALLOWED_ORIGIN`, равным origin'у этого
  фронтенда (по умолчанию `http://localhost:5173`, т.е. `npm run dev`);
- при разработке на разных портах/доменах это обязательно must — без
  совпадающего CORS-конфига браузер откажется сохранять cookie.

## Структура

```
src/
  api/client.js           обёртка над fetch (credentials, разбор ошибок)
  context/AuthContext.jsx состояние аутентификации (user, login, register, logout)
  utils/
    date.js                календарная сетка, относительные даты, сравнения
    useTheme.js            хук переключения/персистентности темы
  components/
    AuthScreen.jsx         вход / регистрация
    Sidebar.jsx             системные фильтры + папки + переключатель темы
    TaskList.jsx              центральная колонка: заголовок, счётчик, QuickAdd, список
    TaskRow.jsx                 одна строка задачи в списке
    QuickAdd.jsx                 быстрое добавление с progressive disclosure
    DatePicker.jsx                кастомный календарь-попап
    PriorityPicker.jsx             попап выбора приоритета
    TagPicker.jsx                   попап поиска/создания тега
    PriorityDot.jsx                  цветной индикатор приоритета (общий)
    TagBadge.jsx                     бэйдж тега (общий)
    TaskDetail.jsx                    правая панель: инлайн-редактирование,
                                       история, архивация/удаление
    Toast.jsx                         всплывающее сообщение об ошибке
  app.css                  все стили компонентов
  index.css                design tokens (light + dark через [data-theme]),
                            сброс стилей, типографика
```

## Сборка

```bash
npm run build
```

Собранные файлы попадают в `dist/` — раздавайте их любым статическим
сервером или через nginx/Caddy перед Go-бэкендом.
